# E39: continuous Dyna loop: dream policies win 68% of real radiant games (holdout), up from 34%

**Status:** running (2026-10-05). The loop runs continuously; the numbers below are as of 13:45.

**Verdict:**
- **A continuous, asynchronous Dyna loop** (world model, PPO, real-game collection and evaluation all running at the same
  time) takes the best dream policy from **101/300 (34%) to 203/300 (68%)** real radiant wins against the shipped net,
  measured on 300 games per side whose seeds were never used to choose a checkpoint.
- **Two changes stopped the decline every earlier PPO run showed:**
  - removing the death penalty from the dream reward;
  - a KL penalty toward the best real-game policy (the anchor), which moves to each new real-game best.

  Without them, real wins fell from about 30/60 to 0–8 within 4–6 updates, whatever the learning rate.
- **Dire: 0 wins everywhere.**

Every number comes from `results/moba/dream/DYNA_LIVE_TABLE.md`, generated by `scripts/moba/dyna_live_table.py` from
the logs listed there.

## 1. The loop

Four workers that never wait for each other, and a controller on the Mac that relays between them
(`scripts/moba/sweeps/dyna_live.py`, a copy of `runs/pod/dyna_live.py`):

| worker | pods | what it does |
|---|---|---|
| world model | dl0–dl6: 6 A40 + an A100 rank 0, FedAvg every 50 updates | trains without stopping (`--live-data`); a quarter of every batch comes from the 10 newest files (100 games) of the policy's real games, reloaded when new files arrive; rank 0 checkpoints every 200 updates |
| PPO | dl12–dl19: 8 A40, FedAvg every update | trains without stopping; swaps in each new world-model checkpoint, every rank at the same update (`--wm-watch`); restarts from or anchors to a policy when told (`--reset-watch`, `--anchor-watch`) |
| collector | evc4: 32-core CPU pod, 6 workers | forever plays 10 real games of the newest PPO policy against the shipped net, then records, replays, verifies and uploads them (`scripts/moba/dyna_live_collect.py`) |
| evaluator | evc1: 32-core CPU pod | 60 real games per side for every new PPO policy, on the fixed seeds 50000000+ |

- **Headstart:**
  - world model `wm_r1` (fleet20e ×1.5 + 500 updates on 270 games of `dyna3_r1`);
  - PPO and collector from `all_handcrafted` u0017 (E38);
  - the `dyna3_r1` games are the first live files.
- **PPO:** the E38 `all_handcrafted` reward, 1,400-tick episodes, 128 games per pod, 16 minibatches, `--gpu-opp`.
  About 135k steps/s for the fleet, one update every ~60 s.
- **Drift guard:** if the last 3 evaluated policies each won at most half of the anchor's fixed-seed wins, every PPO rank
  restarts from the anchor at the same update.
- **Anchor selection (from ppol3 on):**
  1. A policy that matches the anchor on the fixed seeds is played on 300 games per side on the fresh seeds 60000000+.
  2. If it wins at least 9 more radiant games than the anchor (about one standard error), it becomes the KL anchor and
     the reset target on every PPO rank.

## 2. Results on fresh and holdout seeds (300 games per side, vs the shipped net)

| policy | fresh seeds (60000000+, used to pick anchors) | holdout seeds (70000000+, never used) | towers/game (holdout) |
|---|---|---|---|
| u0017 (start, E38) | 88 (29%) | 101 (34%) | 3.37 |
| ppol u71 | 148 (49%) | 159 (53%) | 3.77 |
| ppol4 u10 (anchor at 12:47) | 178 (59%) | 167 (56%) | 3.86 |
| **ppol4 u49 (anchor at 13:23)** | 193 (64%) | **203 (68%)** | 3.90 |

- **u0017 → u71 (+58 holdout games) and u71 → u49 (+44) are real:** about 5 and 3.6 standard errors of the difference.
- **u71 → u10 (+8) is not.** u10's fresh-seed lead was mostly selection on reused seeds, which is why the holdout set
  exists.
- **The fixed 60 seeds overstate the best checkpoints.** u0017 was picked as E38's best on them at 45%, but wins 29–34%
  on new seeds.

## 3. Why every earlier run declined, and what fixed it

| run | setting | updates evaluated | radiant wins (fixed seeds): mean / min / max | points with ≤ 8 wins | drift resets |
|---|---|---|---|---|---|
| ppol | lr 3e-4, death penalty on, no KL | 46 | 14.8 / 0 / 34 | 13 | 5 |
| ppol2 | lr 5e-5, death penalty on, no KL | 43 | 13.8 / 0 / 35 | 19 | 4 |
| ppol3 | lr 5e-5, death penalty 0, KL 1.0 to anchor | 6 | 34.8 / 32 / 37 | 0 | 0 |
| ppol4 | lr 5e-5, death penalty 0, KL 0.3 to anchor | 31 | 32.1 / 20 / 41 | 0 | 0 |

**Diagnosis.** All of it is on ppol2, updates 27–55, joining rank 0's dream log with the per-game arena records;
`results/moba/dream/drift/`.
- **No dream metric tracks real wins.** Correlation with real wins over 29 updates:
  - dream reward +0.23;
  - XP +0.29;
  - deaths +0.16;
  - our towers −0.10;
  - the net's towers +0.35;
  - entropy −0.37;
  - KL +0.34.

  Even at the real-game peaks, the dream has the net out-taking us in towers (0.6–0.95 vs 0.1–0.45 per episode).
- **Real-game behaviour tracks the drift clearly.** As the policy drifts it stops fighting:

  | real games | wins | kills | deaths | creeps | the net's level | game length (ticks) |
  |---|---|---|---|---|---|---|
  | right after a reset | 24–35/60 | 1.4–1.6 | 5.2–6.0 | 36–38 | 5.2 | ~5,700 |
  | end of the drift | 0–5/60 | 0.5–0.7 | 2.9–3.4 | 31–33 | 4.0 | ~6,000, the limit |

- **It is not the learning rate.** Cutting it 6× (3e-4 → 5e-5) cut the per-update KL 3× (median 0.0071 → 0.0022) and
  the clip fraction from 0.08 to 0.01. The collapse still took the same 4–6 updates.

**Ablation.** All arms from u71, lr 5e-5, the world model frozen at `wml` @3600, no resets, 60 games per side per point:

| arm | pods | radiant wins by update | at the last point: towers / kills / deaths / game length |
|---|---|---|---|
| entropy bonus 0 | 3 | 22 → 23 → 17 → 3 → 4 → 3 → 0 → 0 (u5 → u21) | 1.95 / 0.61 / 5.0 / 6,000 |
| death penalty 0 | 3 | 27 → 35 → 28 → 32 → 24 → 30 → 17 → 19 (u6 → u22) | 2.8 / 0.67 / 4.2 / 5,814 |
| KL to u71, coef 1 | 2 | 35 → 35 → 30 → 41 → 38 → 29 → 29 → 32 (u6 → u22) | 4.0 / 1.52 / 6.1 / 5,616 |

- **The entropy bonus is not the cause.** With it at 0 the arm collapses the same way.
- **The death penalty is part of it.** Removing it delays the decline by about 10 updates, but not past u20.
- **The KL penalty holds through u22** (one seed per arm; arms on 2–3 pods vs the runs' 8).

**Fix in the loop.** ppol3/ppol4 use death penalty 0 plus KL toward the anchor:
- **KL coef 1.0 (ppol3)** held the policy at the anchor (fresh 146–151 vs 148) without improving it.
- **Coef 0.3 (ppol4)** let it improve. Anchors u5 → u10 → u49, the last confirmed on the holdout seeds (§2).

## 4. The world model in the loop

- **Throughput:** 0.5 updates/s for the 7-pod fleet; a new checkpoint reaches PPO every ~7 minutes.
- **Live loss** (on the policy's newest games) started at 18–19 vs about 14 on the base data, and is 14.9–15.9 later.
- **Two failures (the stated design was not what ran for most of `wml`):**
  - The `wml` followers ran out of GPU memory one by one while reloading the live store (old and new stores were in memory
    together). From update ~1,550 the fleet was rank 0 alone.
  - Rank 0 crashed at update 3,675 on a truncated live file. The WM was then frozen at 3,600 until `wml2` started at 12:16.

  Fixed: the old store is freed first, and unreadable files are skipped and logged. `wml2` runs on all 7 pods.
- **Collector:**
  - The truncated files came from evc4's disk filling up at ~11:40: it kept every dense file locally, 76 GB. Two truncated
    files reached S3 (`games.1010630.mbs`, 42 MB; `games.1000630.mbs`, 91 MB) and are left there.
  - From ~11:40 to 13:40 no new games were collected, so the WM trained on the same 10 live files.
  - Fixed: the worker deletes its local files after the md5-verified upload. All 382 local files matched S3 by size before
    deletion.
  - 4,060 games collected so far.
- **This experiment does not isolate the world model's contribution.** The PPO changes (§3) and the continuously trained
  world model act together. No arm ran the same PPO in a frozen world model for the whole run.

## 5. Not shown

- **Dire:** 0 wins in every evaluation of every run.
- **Seeds:** one seed per PPO configuration. The 68% is one policy's holdout score, not a distribution over runs.
- **No game-logic rules were added to the world model or the dream.** The changes are reward weights (`--death-scale 0`)
  and a training penalty (KL).

## Infrastructure and incidents

- **Pool:** the 20-pod pool got only 15 pods (dl7–dl11 never got capacity), split 7 WM / 8 PPO.
- **Remote `pkill -f <pattern>` killed its own ssh shell** (the pattern matched the command), so setup steps silently
  didn't run. Patterns are now bracketed (`[m]obawm...`).
- **Two arena runs on one CPU pod hang each other**, and so does a single 300-game run. Seed checks run alone as five
  60-games-per-side chunks (`scripts/moba/sweeps/seed_check.py`), and the evaluator kills orphaned workers first.
- **Cost (I):** about 15 GPU pods + 2 CPU pods at $12.46/hr from 09:12, about $60 so far.
